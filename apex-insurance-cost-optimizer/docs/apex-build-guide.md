# APEX build guide (reference app)

You build the app in your own Oracle APEX workspace. This guide gives the steps and the SQL, and the numbers you should see at each checkpoint (computed on the synthetic data in `data/`). Send screenshots and any error text at each checkpoint.

Nothing here has been run on Oracle by the author of this repo. Expect small fixes on the first run, and treat the checkpoint numbers as the test.

## Part 0. Workspace
Use either an Always Free Autonomous Database with APEX (Oracle Cloud) or a workspace on apex.oracle.com. Steps are the same from SQL Workshop onward. Note the Always Free instance stops after 7 days of inactivity and may be reclaimed after 90 cumulative inactive days, so keep your export in GitHub.

## Part 1. Create the tables and load the data

1. SQL Workshop, SQL Scripts, Upload: run `db/01_schema.sql`, then `db/02_reimbursement_rules.sql`. Use SQL Scripts, not SQL Commands, because the files hold many statements.
2. Skip `db/04_security_audit.sql` and `db/05_insurer_integration.sql` for now. They are sketches.
3. SQL Workshop, Utilities, Data Workshop, Load Data. Load each CSV into the existing table of the same name, in this order: providers, insurance_plans, members, drug_master, prescriptions, dispense_records, claims, stock_wastage.
   - Choose "Existing table" and map columns by name.
   - Set the date format to `YYYY-MM-DD` for every date column.
   - Leave the id columns mapped. They load because the keys are `GENERATED BY DEFAULT ON NULL`.
4. Run `db/03_advisories_billing.sql`, then load `data/advisories.csv` into `advisories`.
5. Move each identity forward so new rows do not collide with loaded ids, for each loaded table, for example:
   `ALTER TABLE claims MODIFY claim_id GENERATED BY DEFAULT ON NULL AS IDENTITY (START WITH LIMIT VALUE);`

### Recommended: load with the generated SQL scripts
The wizard can be slow or reject dates. `data/sql/` holds the same data as INSERT scripts with ANSI date literals, so no date mask is needed. They were generated by `synthetic_data/make_sql_load.py` and checked on SQLite against the CSVs (every row and cell matched), but not run on Oracle.
1. If a failed or cancelled wizard load left rows behind, clear that table first, for example `DELETE FROM prescriptions; COMMIT;`, and check the counts of the tables above it.
2. SQL Workshop, SQL Scripts, Upload, then Run each file in the order of its number prefix: `01_providers_part1.sql`, `02_...`, up to `09_advisories_part1.sql`. Tables with more rows have parts (`05_prescriptions_part1.sql` to `part4`); run the parts in order.
3. Skip files for tables the wizard already loaded correctly (check the row counts).
4. Then go on to the identity step and the checkpoints.
If you type a date mask in the wizard, type it without quotes: `YYYY-MM-DD`. A mask with double quotes around it is read as literal text and rejects every row.

### If a load fails (for example prescriptions)
The error table always shows every column as text, because it holds the raw file values. A varchar column there is normal. The real cause is in the error message column of that table. Check these in order:
1. **Date format.** Every date in the CSVs is `YYYY-MM-DD`. In the Load Data wizard, set the format mask of each date column to `YYYY-MM-DD` (prescriptions: `rx_date`; dispense_records: `dispense_date`, `batch_expiry`; claims: `claim_date`; stock_wastage: `written_off`; advisories: `decided_at` is empty, leave it). Typical errors: ORA-01861 or ORA-01843. If all rows fail, this is almost always the reason.
2. **Missing parent rows.** If only some rows fail with ORA-02291, a parent table (members, providers, drug_master, dispense_records) was not fully loaded. Check its row count first, then reload this table.
3. **Old schema.** If the error is ORA-32795, the tables were created with the old `GENERATED ALWAYS` keys. Re-run the current `db/01_schema.sql`.

Reliable fallback, which avoids the wizard's date handling: load the CSV into a staging table with every column as text, then convert.

```sql
CREATE TABLE prescriptions_stg (
  rx_id VARCHAR2(20), member_id VARCHAR2(20), provider_id VARCHAR2(20),
  drug_id VARCHAR2(20), rx_date VARCHAR2(20), rx_qty VARCHAR2(20));
-- load data/prescriptions.csv into prescriptions_stg with Data Workshop (all text)
INSERT INTO prescriptions (rx_id, member_id, provider_id, drug_id, rx_date, rx_qty)
SELECT TO_NUMBER(rx_id), TO_NUMBER(member_id), TO_NUMBER(provider_id),
       TO_NUMBER(drug_id), TO_DATE(rx_date,'YYYY-MM-DD'), TO_NUMBER(rx_qty)
  FROM prescriptions_stg;
COMMIT;
DROP TABLE prescriptions_stg;
```

Use the same pattern for the other tables with dates, converting each date column with `TO_DATE(col,'YYYY-MM-DD')` and each amount with `TO_NUMBER(col)`. Empty text becomes NULL in Oracle, which is what the empty `approved_amount` and `rule_code` cells need.

## Part 3. Page 1: Leakage overview
Create page 1 as a Blank Page named "Leakage overview". Add regions in this order.

### Region A: KPI cards
Region type: Cards (or Classic Report with a Template Options layout of Value Attribute pairs if you prefer). SQL source:

```sql
SELECT 'Total claimed' title, TO_CHAR(SUM(claimed_amount),'FM99G99G99G990') value FROM claims
UNION ALL
SELECT 'Total leakage', TO_CHAR(SUM(leakage_amount),'FM99G99G99G990') FROM v_claim_leakage
UNION ALL
SELECT 'Leakage share of claimed',
       TO_CHAR(100 * (SELECT SUM(leakage_amount) FROM v_claim_leakage)
               / (SELECT SUM(claimed_amount) FROM claims), 'FM990.0') || '%' FROM dual
UNION ALL
SELECT 'Claims with leakage', TO_CHAR(COUNT(*),'FM99G990') FROM v_claim_leakage;
```

Expected values: 1,55,90,259 claimed and 24,96,023 leakage (the format mask groups digits the Indian way, 2 digits after the first 3); 16.0%; 3,224 claims.

### Region B: leakage by cause
Region type: Chart, type Bar (horizontal). Series SQL:

```sql
SELECT leakage_type label, ROUND(SUM(leakage_amount),0) value
  FROM v_claim_leakage GROUP BY leakage_type ORDER BY 2 DESC
```

Label column `LABEL`, value column `VALUE`. Set the value format with a prefix of the rupee sign.

### Region C: leakage by month, stacked
Region type: Chart, type Bar (vertical), Stack: on. Series SQL:

```sql
SELECT TO_CHAR(claim_month,'YYYY-MM') month_label,
       leakage_type series_name,
       ROUND(SUM(leakage_amount),0) value
  FROM v_claim_leakage
 GROUP BY claim_month, leakage_type
 ORDER BY claim_month
```

Set Series Name to the `SERIES_NAME` column, Label to `MONTH_LABEL`, Value to `VALUE`, and turn on "Group by series". The month labels must read 2025-01 to 2025-12 or similar, with no gaps.

### Region D: leakage by provider
Region type: Chart, type Bar (horizontal). Series SQL:

```sql
SELECT p.provider_name label, ROUND(SUM(l.leakage_amount),0) value
  FROM v_claim_leakage l
  JOIN claims c            ON c.claim_id = l.claim_id
  JOIN dispense_records ds ON ds.dispense_id = c.dispense_id
  JOIN prescriptions rx    ON rx.rx_id = ds.rx_id
  JOIN providers p         ON p.provider_id = rx.provider_id
 GROUP BY p.provider_name ORDER BY 2 DESC
```

Expected, in order: Synthetic General Hospital 746,891; Synthetic Metro Hospital 695,129; Synthetic Care Pharmacy 463,487; Synthetic City Clinic 335,778; Synthetic Community Clinic 254,737. They sum to 2,496,022.62 before rounding.
